# NLP Project:  Исследование влияния Retrieval-Augmented Generation на качество ответов и уровень галлюцинаций в задаче Question Answering


Проект посвящён сравнению классических и LLM-подходов в задаче **Question Answering**. Основная идея работы — проверить, помогает ли подход **Retrieval-Augmented Generation (RAG)** повысить качество ответов и снизить количество неподтверждённых ответов по сравнению с LLM, которая отвечает без внешнего контекста.

В проекте рассматривается русскоязычный QA-набор данных **SberQuAD**, а также несколько дополнительных мини-экспериментов: влияние языка, популярности информации и размера модели.

---

## Актуальность

Современные языковые модели могут хорошо отвечать на вопросы, но у них есть важная проблема: модель может уверенно сгенерировать ответ, который не подтверждается исходными данными. Такие ответы часто называют **галлюцинациями**.

В задачах Question Answering это особенно критично, потому что пользователю нужен не просто красивый текст, а точный ответ, основанный на конкретном контексте. Поэтому в проекте проверяется гипотеза: если перед генерацией ответа сначала находить релевантный фрагмент текста и передавать его модели, то качество ответа должно стать выше, а риск галлюцинаций — ниже.

---

## Цель проекта

Цель работы — построить и сравнить несколько QA-подходов и оценить, насколько использование RAG влияет на качество ответов и уровень потенциальных галлюцинаций.

Основные задачи:

- подготовить данные для экспериментов;
- реализовать базовый TF-IDF sentence baseline;
- проверить LLM без внешнего контекста;
- реализовать RAG с TF-IDF retrieval;
- реализовать RAG с E5 embedding retrieval;
- сравнить подходы по QA-метрикам;
- отдельно исследовать влияние языка, популярности информации и размера модели.

## Предобработка

Предобработка была минимальной, чтобы не исказить исходную QA-задачу.

В проекте выполнялись следующие шаги:

- извлечение первого корректного ответа из поля `answers`;
- фильтрация некорректных записей;
- нормализация текста для метрик: нижний регистр, удаление пунктуации, нормализация пробелов;
- разбиение контекстов на чанки для RAG;
- использование `chunk_size = 200`, `300`, `500` слов;
- использование `overlap = 50` слов;
- отдельная токенизация для расчёта `Exact Match` и `Token F1`.

## Подходы

В работе сравнивались четыре основных подхода.

### 1. TF-IDF sentence baseline

Простой и интерпретируемый baseline без LLM. Контексты разбиваются на фрагменты, затем для вопроса ищется наиболее похожий фрагмент через TF-IDF и cosine similarity. После этого возвращается наиболее подходящее предложение.

Плюс подхода — простота и скорость. Минус — сильная зависимость от совпадения слов. Если вопрос переформулирован, TF-IDF может найти не самый точный фрагмент.

### 2. LLM без RAG

В этом варианте модель получает только вопрос и генерирует ответ без исходного контекста. Такой подход нужен как baseline, чтобы проверить, насколько модель может отвечать из внутренних знаний.

Главный минус — модель не видит текст SberQuAD, поэтому часто угадывает, отказывается отвечать или генерирует неподтверждённый ответ.

### 3. LLM + RAG с TF-IDF retrieval

Основной подход проекта. Сначала TF-IDF retrieval ищет релевантные чанки, затем найденный контекст передаётся в LLM вместе с вопросом.

Идея подхода: модель должна отвечать не из памяти, а по найденному фрагменту текста.

### 4. LLM + RAG с E5 embedding retrieval

В этом варианте для поиска используются не TF-IDF признаки, а dense embeddings модели `intfloat/multilingual-e5-small`. Такой retrieval лучше учитывает смысловую близость текста и вопроса, а не только совпадение отдельных слов.

Минус подхода — он требует больше вычислительных ресурсов. Кроме того, хороший retrieval не всегда гарантирует лучший итоговый ответ, потому что после поиска ещё остаётся этап генерации.

В проекте использовались следующие модели и инструменты:

## Метрики

Для оценки качества использовалось несколько метрик.

| Метрика | Что показывает |
|---|---|
| `Exact Match` | Доля ответов, которые полностью совпали с эталоном после нормализации |
| `Token F1` | Частичное совпадение между токенами предсказания и правильного ответа |
| `retrieved_contains_answer_rate` | Доля случаев, когда правильный ответ был найден в top-k чанках |
| `hallucination-like rate` | Эвристическая доля неподтверждённых ответов |
| `refusal rate` | Доля отказов модели от ответа |

Основной метрикой для сравнения был выбран **Token F1**, потому что для генеративных моделей ответ может не совпадать с эталоном дословно, но при этом быть частично правильным.

---

## Протокол экспериментов

Проект выполнен как evaluation-only исследование. Модели не обучались с нуля и не дообучались. Вместо этого сравнивались разные QA-пайплайны на фиксированных подвыборках данных.

Основные условия:

- основной корпус: 1500 записей из SberQuAD validation;
- retrieval / baseline эксперименты: 250 вопросов;
- LLM-эксперименты: 30 вопросов;
- языковой эксперимент: 20 русских и 20 английских примеров;
- эксперимент по размеру модели: 10 примеров;
- `seed = 42`;
- `temperature = 0.0`.

Варьируемые параметры:

- размер чанка: `200`, `300`, `500` слов;
- `top_k`: `1` и `3`;
- тип retrieval: `TF-IDF` и `E5 embeddings`;
- prompt: `plain` и `strict`;
- язык: русский и английский;
- размер модели: `0.5B` и `1.5B`.

## Основные результаты

| Подход | Настройки | n | EM | Token F1 | Hallucination-like rate | Retrieval |
|---|---|---:|---:|---:|---:|---:|
| TF-IDF sentence baseline | chunk=300, top_k=3 | 250 | 0.0040 | 0.2346 | 0.5160 | 0.8800 |
| LLM без RAG | prompt=plain | 30 | 0.0000 | 0.0621 | 0.9000 | — |
| LLM без RAG | prompt=strict | 30 | 0.0000 | 0.0564 | 0.8000 | — |
| LLM + RAG | TF-IDF, chunk=300, top_k=3, prompt=strict | 30 | 0.1333 | 0.4388 | 0.2667 | 0.8667 |
| LLM + RAG | TF-IDF, chunk=300, top_k=3, prompt=plain | 30 | 0.1667 | 0.4628 | 0.2667 | 0.8667 |
| LLM + RAG | E5, chunk=300, top_k=3, prompt=strict | 30 | 0.1667 | 0.4127 | 0.4000 | 0.9667 |

Лучший основной результат показал вариант:

```text
LLM + RAG, TF-IDF retrieval, chunk=300, top_k=3, prompt=plain, temperature=0.0
```

Он получил:

- `Exact Match = 0.1667`;
- `Token F1 = 0.4628`;
- `hallucination-like rate = 0.2667`;
- `retrieved_contains_answer_rate = 0.8667`.

По сравнению с LLM без RAG качество выросло примерно с `Token F1 ≈ 0.06` до `Token F1 ≈ 0.46`, а доля неподтверждённых ответов снизилась с `0.80–0.90` до `0.2667`.

## Пример ошибки без RAG

Один из показательных примеров связан с вопросом:

```text
Кто сочетает в себе образы своих сёнэн-предшественников?
```

Правильный ответ:

```text
Наруто Удзумаки
```

LLM без RAG дала нерелевантный ответ:

```text
Сёнэн-предшественниками являются древние русские писатели
```

Такой пример показывает главную проблему LLM без внешнего контекста: модель может уверенно сгенерировать ответ, который не связан с исходным текстом.

---

## Основные выводы

1. **RAG заметно улучшает качество ответов** по сравнению с LLM без внешнего контекста.
2. **LLM без RAG часто ошибается**, потому что не видит исходный текст и отвечает из внутренних знаний.
3. **TF-IDF baseline оказался лучше, чем LLM без RAG**, но хуже RAG-подходов, потому что он умеет находить релевантный фрагмент, но плохо формулирует короткий ответ.
4. **Лучший результат показал LLM + RAG с TF-IDF retrieval** при `chunk_size=300`, `top_k=3`, `prompt=plain`.
5. **E5 retrieval дал самый высокий retrieval rate**, но это не привело к лучшему итоговому Token F1.
6. **RAG помогает на разных типах экспериментов**: на русском и английском языке, на популярных и контекстно-зависимых фактах.
7. **Размер модели не является главным фактором качества**, если модель не получает релевантный контекст.

## Ограничения работы

У проекта есть несколько ограничений:

- LLM-эксперименты проводились на небольшой подвыборке из-за времени генерации;
- `hallucination-like rate` является эвристикой, а не полноценной ручной фактологической проверкой;
- качество RAG сильно зависит от retrieval-этапа;
- EM и Token F1 не всегда идеально оценивают смысловую близость генеративного ответа;
- E5 retrieval требует больше вычислительных ресурсов, чем TF-IDF.
